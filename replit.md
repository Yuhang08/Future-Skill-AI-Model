# FutureSkill AI collaboration notes

- Keep the existing FastAPI application and assessment/reskilling behavior. Do not rebuild the project in another framework.
- Use the stable screen IDs on `/__dev/screens` when scoping UI work. Preserve the current appearance unless a requested change calls for a redesign, and keep accepted changes when refining later.
- Keep development-only demos isolated from normal learner sessions. Label sample data, simulations, and proposed features clearly.
- Mark a screen visually verified only after rendering it in Preview. Keep trend scenarios and the current SDG pathway links labeled as prototypes: the SDG links use illustrative skill requirements and do not establish employment or SDG impact. CV input and employer sharing remain unimplemented.
- For UI changes, report the affected IDs, Preview location, checks performed, and any limitation. Ask before deleting data, removing a major feature, or making a broad structural change.
